## Что сделано

- Этапы 1–3: бесконечные 75-секундные циклы Settle/Build/Pressure/Release, плавные потолки скорости и частоты, детерминированный бюджет угроз, честные предупреждения, подготовленная первая волна после 1,2 секунды, бонусы в допустимых окнах каждые 35–50 активных секунд.
- Этап 4: таймлайны вступления, полёта бонуса (90 мс удержание + 800 мс полёт), замены, активации и пояснений аномалий; безопасные запасные подписи для неизвестных ID.
- Этап 5: ограниченные по времени/количеству эффекты, раздельные характеры SLOW/PULSE/CLEANSE/COLOR BREAK, подсказки аномалий, reduced motion.
- Этап 6: шесть Canvas-слоёв, матовая сборка хаба, направляющие первой волны, читаемый падающий бонус, локальные удары/фрагменты, корректные DRIFT/INERTIA-маркеры и перелёт бонуса. Несколько замечаний независимого ревью исправлены; итоговый код принят.
- Этап 7: постоянный HUD-слот с названием, описанием и клавишей «ПРОБЕЛ»; счёт/множитель/фаза сверху, предупреждения возле затронутых сторон, устойчивые DOM-узлы и фокус, одно голосовое объявление для двойного предупреждения. Независимое ревью и правки завершены.
- Этап 8: настоящее вступление на PLAY/RETRY, синхронизация игровых и визуальных часов, детерминированный перезапуск, расширенный публичный снимок состояния для QA.
- Этап 9: актуальные README/SOURCE, исходники в дистрибутиве, публичный браузерный QA для 29 обязательных и 18 дополнительных сценариев на 1280×720 и 1920×1080.
- Визуальный QA-фикс: убраны сплошные цветовые заливки и дублирующиеся Canvas-подписи; аномалия показывает одну читаемую подпись у центра, не обещая будущую сторону. Обычное завершение цикла имеет короткое отдельное сообщение, которое уступает место предупреждению «ОПАСНО» при тесном верхнем поле. Точечное независимое ревью прошло без блокирующих замечаний.
- Финальное ревью: DRIFT одинаково приземляется при крупных и мелких шагах времени; скрытый хвост спирали не переходит из Pressure в Release; предупреждение аномалии находится у центра до появления реального затронутого блока, после чего его фактический маршрут отмечается на поле.

## Перенос на другой ПК

Актуальный полный Git bundle будет лежать рядом с папкой проекта: `C:\Users\qqqma\OneDrive\Desktop\nice\hextris-remake-2026-09-27.bundle`. Старый `hextris-remake-2026-09-23.bundle` **не содержит новые этапы** и не подходит для актуального переноса. На другом ПК из папки с новым bundle выполнить:

```powershell
git clone -b codex/hextris-remake .\hextris-remake-2026-09-27.bundle hextris-remake
cd hextris-remake
```

Если хочешь именно GitHub/push/pull, сначала нужен адрес **твоего** GitHub-репозитория. Добавь его как отдельный remote `github` и отправь ветку туда (`git push -u github codex/hextris-remake`); не используй нынешний `origin` с путём к старому bundle. После получения ветки на другом ПК в папке проекта выполнить:

```powershell
npm.cmd ci
npm.cmd run test:run
npm.cmd run dev -- --host 127.0.0.1
```

Открыть `http://127.0.0.1:5173/`. В PowerShell использовать именно `npm.cmd`, чтобы не упереться в запрет запуска `npm.ps1`. Не добавлять `\` в конце адреса хоста. Если переносится не Git-ветка, а целая папка, `node_modules` и `dist` можно не копировать — `npm.cmd ci` и `npm.cmd run build` восстановят их.
